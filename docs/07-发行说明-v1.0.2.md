## 一、这个版本解决了什么（重要）

v1.0.0 / v1.0.1 刷进相机后一启动就显示 **「相机初始化失败」**、**没有实时预览**、
**参数调不动**、**按确认键也没有对焦/快门反应**。v1.0.2 修掉了这个根因。

### 根因：编译期桩把静态方法写成了实例方法

本项目的索尼私有 API 编译期桩（`com.sony.scalar.hardware.CameraEx` 等）是由
jasmin 反汇编生成的。旧版生成器**丢失了方法修饰符**，把固件里真正的方法：

```
.method public static open(ILcom/sony/scalar/hardware/CameraEx$OpenOptions;)Lcom/sony/scalar/hardware/CameraEx;
```

错写成了实例方法：

```java
public CameraEx open(int id, CameraEx.OpenOptions options) { ... }   // 错：非静态
```

于是应用里写的 `new CameraEx().open(0, null)` 在真机上抛 `NoSuchMethodError`，
被 `catch (Throwable)` 吞掉 → 界面只显示“相机初始化失败”，后续预览/按键/快门全部不可用。
同理，`CameraEx$StoreImageInfo` 的 `FileName` / `DirectoryName` 等字段在固件里是**实例字段**，
旧桩却写成了 `public static final String`，即使相机能打开，取文件名也会拿到 `null`。

### v1.0.2 的修改

| 位置 | 修改 |
| --- | --- |
| `tools/stubs/jasmin2java.js`（桩生成器） | 解析并保留 `static/final/abstract` 修饰符；`static` 字段才输出 `static`，其余输出实例字段；类里若**没有** `<init>` 则生成 `private 类名() {}`（防止再误用 `new`）；有 `<init>` 才生成公开构造器 |
| `CaptureService.open()` | 改为 `cameraEx = CameraEx.open(CAMERA_ID, null);`（**静态调用**，与索尼样例/OpenMemories 的 TimeLapse 实现一致） |
| `CaptureService.takePicture()` | 快门触发由 `Camera.takePicture(...)` 改为 **`CameraEx.burstableTakePicture()`** —— 这是索尼 PMCA 运行时里真正可用的静图拍摄入口 |
| `CaptureService.handleShutterStatus()` | 收到快门回调后先 `cancelTakePicture()`，再按需 `startPreview()` 恢复预览，然后按 `STATUS_OK/CANCELED/ERROR` 分派 |
| `CaptureService` | 新增 `getLastError()`：初始化失败时把**真实异常类名+消息**显示到屏幕上，不再是笼统一句话 |
| `CaptureActivity` | 新增 **APO 抑制**：前台时向 `com.android.server.DAConnectionManagerService.apo` 发 `apo_info="APO/NO"`（禁止自动关机），退到后台/退出时发 `APO/NORMAL` 恢复。间隔拍摄要长时间开机，这一步必须有，否则相机会自己关机 |
| `CaptureActivity` | 新增按键诊断角标（`DEBUG_OVERLAY`）：屏幕右下角显示 `scan=<扫描码> key=<键码> act=<动作> cam=OK/FAIL`，用于实机排查按键映射 |
| `UiTheme` / `SettingsScreen` | 新增 `drawTextWrapped()` 文本折行，状态/错误信息最多显示 2 行，长异常信息不再被截断 |

## 二、安装 / 升级

```powershell
# 覆盖安装（versionCode 3 > 2，可直接升级，无需先卸载）
pmca-console-v0.18-win.exe install -f releases\PMCA_IntervalCapture-v1.0.2.apk
```

看到 `Task completed successfully` 即成功；随后**相机关机再开机**，
`MENU → 应用程序 → 应用程序列表 → 间隔拍照` 启动。

> USB 传输层报错（`MTP SendCommand failed: 0x-7ff8fe4f`、`0x800703E3`、`No devices found`）
> 与 APK 无关，是相机在切 MTP/app-install 模式时重新枚举设备导致的，重跑 2~5 次即可。

## 三、装好后请按这三步确认

1. 参数页是否还显示「相机初始化失败」——正常应显示参数列表与硬件提示；
2. 按 `上/下` 键，右下角诊断角标的 `scan=` 数字是否变化（变了说明按键路由通了）；
3. 按 `确认键` 是否能开始拍摄、屏幕右侧是否出现实时预览。

如仍失败，请把屏幕上显示的**完整错误文字**（新版本会显示真实异常名）或
SD 卡 `/PMCACAP/LOG.TXT` 发出来，这是定位问题最快的材料。

## 四、已知限制（与 v1.0.1 相同）

- 最短稳定间隔约 1 秒；单张曝光时间会占用拍摄周期，长曝光时间隔必然漂移，界面会显示溢出次数。
- 图像格式（JPG/RAW/JPG+RAW）以相机机内菜单为准，应用只读取不强行改写。
- 机身温度按每 5 张轮询 `Temperature.getStatus()` 判断（不注册回调，规避固件签名差异）。
- **不调用任何视频录制/编码接口**；完成弹窗选“是”只写 `PMCACAP/TIMELAPSE_JOB.TXT` 任务清单供电脑后处理。
