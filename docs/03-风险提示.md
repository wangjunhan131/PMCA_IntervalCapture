## 一、最重要的一句话

**刷入第三方 PMCA 应用属于非官方支持的操作，存在把相机变成“砖头”的可能。**

“砖”分两种：

| 类型 | 表现 | 能否救回 |
| --- | --- | --- |
| **软件砖（可救）** | 开机卡在应用列表、某项功能异常、应用列表损坏、开机后反复崩溃 | 多数可通过 USB 重连 + 利用固件升级流程重刷官方固件救回 |
| **硬件砖（难救/不可救）** | 开机黑屏无反应、固件校验区被写坏、Bootloader/固件区损坏、USB 完全无响应 | 基本只能送索尼售后，可能被判定为人为损坏而**拒保或高价换主板** |

本项目的应用本身**只安装应用层（APK）**，不触碰固件分区，正常流程**不会**写到固件区。
风险主要来自以下**间接**环节：

1. **安装过程被中断**：安装中途拔线、断电、相机自动关机、电脑休眠/USB 挂起 —— 可能留下写入不完整的应用条目，导致应用列表异常。
2. **相机在此过程异常掉电**（电池电量低、电池接触不良、电池被误取）—— 这是最危险的情形。
3. **混用其他非官方工具**：`updatershell`、`firmware -f` 这类**写固件区**的 PMCA-RE 命令，风险等级远高于“装应用”。**不要对 A6500 使用固件相关命令。**
   （A6500/A6000 均为 BIONZ X 平台（CXD9001x 系列 SoC），PMCA-RE 的 fwupdater 流程对这些平台**不兼容**，强刷固件可能直接变砖。）
4. **安装非本项目的可疑 APK**：来历不明的应用可能误调用固件接口、写坏分区表。只安装你自己编译、自己审计过源码的包。

### 降低变砖风险的操作纪律

- ✅ 电池电量 **≥ 80%**，最好换一块满电原装电池；**全程不要取出电池**。
- ✅ 使用**原装或高质量数据线**，插紧；刷写期间**不要碰相机和线**。
- ✅ 电脑关闭睡眠/休眠；关闭 PlayMemories Home、图片导入、相机相关后台程序。
- ✅ 安装期间**不要**同时在相机上按其他按键。
- ✅ **只装 APK**，绝不执行 `pmca-console firmware`、`updatershell` 等固件区命令。
- ✅ 先在**不在意的老机器**上试，或确认自己承担得起整机损失。
- ❌ 不要在电量低、电池仓松动、“电池电量不准”的电池上操作。
- ❌ 不要在雷雨天/供电不稳的环境给笔记本刷机。
- ❌ 不要为了“省事”跳过签名校验装别人给的 APK。

### 应急处理（万一出问题）

| 症状 | 尝试的处理顺序 |
| --- | --- |
| 开机后应用列表里出现异常项/列表崩溃 | 关机重开 → 进入应用程序列表删除异常应用 → 删除后仍异常则尝试 USB 重装/覆盖安装同一应用 → 再不行走官方固件升级流程重刷 |
| 相机开机就崩溃、无法进入菜单 | **停止盲目操作**。先给电池充满电，断开所有外部设备，再试；仍不行则用索尼官方固件升级工具（ILCE-6500 System Software Update）通过 USB 重刷官方固件 |
| 相机完全无响应（黑屏、USB 不识别） | 取出电池等待 1 分钟再装回；更换满电电池；更换 USB 线与电脑口；仍无反应 → 联系索尼售后 |
| 应用一启动就退回菜单 | 看 SD 卡 `/PMCACAP/LOG.TXT`；大概率是私有 API 与固件不匹配或私有类被误打包（见 02 文档 1.4 自查） |

## 二、机械快门损耗

A6500 是**机械快门**相机，快门寿命没有官方公开数值，消费级经验估算约 **10 万～20 万次**（越低端机身越接近下限，索尼不对此作承诺）。
间隔拍摄是典型的“快门高频消耗”场景，务必算清代价：

| 间隔 | 每天张数（连续 8 小时） | 一个月张数 | 相对 10 万次寿命 |
| --- | --- | --- | --- |
| 1 秒 | 28,800 | 864,000 | 约 **8.6 倍**寿命/月 |
| 5 秒 | 5,760 | 172,800 | 约 1.7 倍寿命/月 |
| 10 秒 | 2,880 | 86,400 | 约 0.86 倍寿命/月 |
| 60 秒 | 480 | 14,400 | 约 0.14 倍寿命/月 |

结论：

- **秒级间隔 + 长时间连续拍摄会显著加速快门磨损**，快门组件更换是收费维修项目。
- 张数不是唯一因素：**反光板/快门帘动作次数**才是。即使使用电子前帘（A6500 支持“电子前帘快门”），
  仍需要机械快门帘收尾，不能等同于纯电子快门。
- 建议：
  - 优先用**较大的间隔**（≥5 秒）做长周期延时；
  - 单次任务**分段**进行（例如每 2 小时停一次，冷却并检查文件）；
  - 把“固定张数”模式设为**你能接受的总张数上限**，不要无脑开无限模式；
  - 长期固定机位延时可以考虑专门的低价机身/二手机身来“扛快门”。

> 本应用已在参数页显示“预计总张数/预计总时长”，并在间隔 <3 秒时给出硬件负载提示，
> 但**提示只是提醒，不会限制你的设置**。请自己评估代价。

## 三、相机过热与热保护

A6500 无机身风扇，散热靠外壳与屏幕。连续拍摄时的发热来源：

1. 传感器长时间通电（预览开启时尤其明显）；
2. 机内 JPEG 编码 / RAW 写入；
3. SD 卡写入（卡本身也发热）；
4. 屏幕常亮（最容易被忽视的一项）。

索尼固件内置**过热保护**，达到阈值会：

- 先在屏幕上显示**温度警告图标**（黄色 → 橙色）；
- 严重时**强制停止录制/拍摄并可能自动关机**；
- 极端情况下会拒绝开机，需要冷却。

本应用的处理：

- `HealthMonitor` 通过 `TempStatus.getStatus()`（`com.sony.scalar.sysutil.didep`）轮询机身/电池温度状态，
  在 `STAT_PREHIGH` 提前警告、`STAT_NEARHIGH` 警示、`STAT_HIGH` **立即停止拍摄并弹出中文报错**；
- 不注册温度**回调**（各固件版本回调方法名不一致，注册会引发 `AbstractMethodError` 崩溃），改为每 5 张轮询一次，更稳妥。

使用建议：

- **关闭预览**（参数页“预览”设为关）能明显降低发热与功耗，是本应用推荐的长时间拍摄配置；
- 环境温度高于 30℃ 时，把间隔拉到 ≥10 秒，或缩短总时长；
- 不要把相机放在密闭包内、阳光直射下、或贴着保温材料拍摄；
- 出现过热停机后，**等机身完全冷却**（至少 10~15 分钟）再继续，不要靠反复重启硬拍。

> **过热是保护机制，不是故障。** 应用主动停机是为了避免更坏的后果；强行继续拍摄可能在关键时刻丢帧/丢文件。

## 四、曝光时长会占用拍摄周期（间隔无法 100% 严格）

这是间隔拍摄的**物理限制**，不是软件 bug：

```
一次拍摄周期 ≈ 快门曝光时间 + 数据读出 + 机内处理/编码 + 写卡时间
```

A6500 官方标称最短拍摄间隔约 **1 秒**，该数值对应**短曝光、JPG、卡速足够**的理想条件。
当下列条件出现时，实际间隔**必然**大于设定值：

| 情况 | 影响 |
| --- | --- |
| 曝光时间变长（如 0.6s、1s、2s、B 门/慢门） | 曝光时间直接吃掉周期 |
| 使用 RAW 或 JPG+RAW | 单张文件 20~25MB+，写入更久 |
| SD 卡速度不足（U1/低速卡） | 写卡成为瓶颈 |
| 机内降噪开启（长曝光降噪） | 曝光后还要等一倍时间做暗场 |
| 电池电量低 | 机内可能降频/延长处理 |
| 机身过热 | 处理速度下降 |

本应用的处理方式（`IntervalScheduler.scheduleNext`）：

- 每张记录**实际耗时**；若单张耗时 ≥ 设定间隔，则判定为**溢出（overrun）**并计数，
  下一张在“上一张开始时间 + 间隔”与“当前时刻”中**取较晚者**，不会试图“补拍”追赶；
- 运行界面会显示**溢出次数**与**上一张耗时**，让你一眼看出实际节拍是否达标；
- 参数页在间隔 <3 秒或格式含 RAW 时给出**硬件限制警告**。

**请接受这个事实：设定 1.0 秒不等于每 1.0 秒一张。**
需要严格等间隔（例如用于科学测量）的场景，请：
调大间隔到单张耗时的 2 倍以上、改用纯 JPG、使用高速卡（U3/V30 以上）、关闭长曝光降噪与预览。
如果要求“绝对等间隔”，只有电子快门机型 + 高速连拍/专业间隔仪才可能接近，A6500 做不到绝对。

## 五、数据安全

- 照片由**相机原生流程**写入 SD 卡（`DCIM/100MSDCF/`），应用**不参与编码、不移动、不删除原图**。
  这是本项目最重要的设计原则：**任何情况下照片优先**。
- 应用自己的文件都在 SD 卡根目录 `PMCACAP/` 下：
  - `LOG.TXT` —— 运行日志（超过 512KB 自动重建）；
  - `SETTINGS.TXT` —— 参数冗余备份；
  - `TIMELAPSE_JOB.TXT` —— **只有你在完成弹窗里选“是”生成视频**时才会出现，只是一个后期任务清单，机内不会生成视频。
- **拔卡前先在相机里关机**。拍摄过程中拔卡 = 丢照片 + 可能损坏文件系统。
- 建议定期把卡内照片拷贝到电脑备份；重要拍摄用**双卡/及时导出**策略（A6500 单卡槽，只能靠及时导出）。
- 应用**不会**自动删除任何照片，也不会自动格式化卡。

## 六、电池与续航

- 间隔拍摄是**长时间开机**场景，A6500 电池（NP-FW50）在开启预览 + 连续拍摄下通常只能撑 **1~2 小时**。
- 应用在运行期间持有 `PARTIAL_WAKE_LOCK`（`PMCACAP:TIMER`）防止相机休眠导致定时器停摆，这会额外耗电。
- 建议：
  - 使用**假电池 + 外接电源（DC 耦合器）**做超长任务；
  - 关闭预览、调大间隔、关闭不必要的机内功能；
  - 任务开始前确认电量 ≥ 50%，中途换电会中断任务（计数不重置，但会漏拍）。
- **电量耗尽可能导致写入中断**，与“变砖风险”一节呼应：不要在低电量下开启长任务。

## 八、风险速查清单（打印/截图带走）

安装前：

- [ ] 电池满电（≥80%），备用电池在手
- [ ] 原装数据线，插紧，电脑不休眠
- [ ] 关闭 PlayMemories Home / 图片导入 / 相机相关软件
- [ ] 相机 USB 模式 = **MTP**（不是海量存储器）
- [ ] 只装自己编译、自己看过源码的 APK
- [ ] 明确知道：**绝不执行固件区命令**（`firmware`、`updatershell`）

使用中：

- [ ] 间隔 ≥ 5 秒（长任务）、优先纯 JPG、卡是 U3
- [ ] 长时间任务关闭预览
- [ ] 设置“固定张数”上限，别用无限模式跑整晚
- [ ] 出现过热提示立即停机冷却
- [ ] 运行界面关注“溢出次数”，它告诉你实际节拍是否达标
- [ ] 拍摄中绝不拔卡、绝不取电池

拍摄后：

- [ ] 相机内关机后再拔卡
- [ ] 检查 `DCIM/` 里照片数量与运行界面计数是否一致
- [ ] 及时备份照片
- [ ] 需要视频时，**在电脑上**用 `PMCACAP/TIMELAPSE_JOB.TXT` 里的命令做后期合成（机内不生成视频）
