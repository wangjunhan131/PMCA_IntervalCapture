# 04 · 需求实现对照表

本表逐条把《任务总纲》里的需求映射到具体代码位置，便于验收与二次开发。
行号基于当前版本源码（统计：Java 15 个文件 / 3696 行，含注释与空行）。

## 一、平台与硬性约束

| # | 需求原文 | 实现位置 | 说明 |
| --- | --- | --- | --- |
| 1 | 必须是 PMCA 相机内置应用，非 Android APK/网页/PC 软件 | `AndroidManifest.xml` + `build-apk.ps1` | 产物是**安装进相机固件的 PMCA 应用**（Android 2.3.7 API 10 运行时），用 Sony 私有 API；无任何网页/PC 代码 |
| 2 | 只使用 PMCA SDK 相机控制接口，不混入安卓 SDK 函数 | `CaptureService.java` | 相机控制只走 `CameraEx`（`com.sony.scalar.hardware.CameraEx`）；`android.hardware.Camera` 仅作为 `getNormalCamera()` 返回的**预览显示载体**（官方推荐用法），不承担拍照 |
| 3 | A6000 最短稳定间隔 1 秒 | `CaptureSettings.INTERVAL_MIN_DS = 10` / `INTERVAL_HARD_MIN_DS = 10` | 内部以 **0.1 秒**为单位存储，最小值 10 = 1.0 秒，硬下限不可突破 |
| 4 | 长曝光占用周期要提示警告 | `CaptureSettings.getHardwareWarning()`；`SettingsScreen.draw()`；`IntervalScheduler.overrunCount` | 参数页实时显示警告；运行中统计溢出次数并显示“上一张耗时” |
| 5 | 支持 JPG / RAW / JPG+RAW，写相机 SD 卡，用原生存储 API | `CaptureSettings.FORMAT_*`；`CaptureService.takePicture()` | `takePicture(shutterCallback, null, null)` 后**存储由固件完成**（走相机原生写卡流程），应用不参与编码/写文件；具体存什么格式由相机机内“影像质量/文件格式”菜单决定，应用在参数页给出对应提示 |
| 6 | 拍第一张后锁定 AE/AF/WB | `CaptureService`（首张 `autoFocus()`，后续不再对焦）；`settings.exposureLock` | 第二张起不再触发对焦动作，复用首张曝光/对焦结果，抑制明暗闪烁；白平衡由机内保持一致 |
| 7 | 无触屏，仅实体按键（上下左右+确认） | `CameraKeyRouter.java` + `CaptureActivity.onKeyDown()` | 全套界面自绘 + 扫描码路由；**没有任何触摸监听代码** |
| 8 | 屏幕分辨率 640×480 | `UiTheme.SCREEN_W=640 / SCREEN_H=480`；`RunScreen.PREVIEW_RECT` | 所有坐标按 640×480 写死；`DialogScreen`/`SettingsScreen` 同 |
| 9 | 只捕获静态图像，不调视频录制接口 | `CaptureService.takePicture()` | 全工程**没有**任何 `MediaRecorder`/`Camera.startRecording`/视频 API 调用（可 grep 验证） |

## 二、参数配置页

| # | 需求 | 实现 | 验收点 |
| --- | --- | --- | --- |
| 1 | 间隔 1.0~3600 秒，步进 0.1 秒，最低 1 秒 | `CaptureSettings`: `INTERVAL_MIN_DS=10`、`INTERVAL_MAX_DS=36000`、`setIntervalDeciseconds()`、`adjust()`；`intervalStep()` 加速步进（<10s→0.1s，<60s→1s，否则→10s） | 设为 0.5 会被钳到 1.0；无法超过 3600.0；按住方向键可快速调 |
| 2 | 模式 A：固定张数 1~9999，拍完自动停 | `SHOT_COUNT_MAX=9999`；`setShotCount()`；`IntervalScheduler.shouldTriggerNow()` 到量后转 `STATE_FINISHED` | 设 3 张必停在第 3 张并弹完成框 |
| 3 | 模式 B：无限拍摄直到手动停止 | `SHOT_COUNT_INFINITE=1000000`（内部哨兵值 > 上限即视为无限）；`getRemainingCount()` 返回 -1 表示无限 | 张数上限再 +1 即显示“无限” |
| 4 | 格式单选：仅 JPG / 仅 RAW / JPG+RAW | `FORMAT_JPG_ONLY=0` / `FORMAT_RAW_ONLY=1` / `JPG_PLUS_RAW=2`；`setImageFormat()`；`SettingsScreen.fieldValue()` | 三态循环切换，互斥 |
| 5 | 曝光锁定开关：开=首张锁定；关=每张重新测光对焦 | `CaptureSettings.exposureLock`；`CaptureService` 内分支 | 开启后画面不闪烁；关闭后每张重新对焦 |
| 6 | 预览开关：关预览降发热、提稳定性 | `CaptureSettings.previewEnabled`；`CaptureService.startPreview()/stopPreview()`；`CaptureActivity` 中上方键可运行时切换 | 运行页按 `↑` 立即开/关预览 |

## 三、运行状态界面

| # | 需求 | 实现 | 验收点 |
| --- | --- | --- | --- |
| 1 | 已拍数量 | `IntervalScheduler.takenCount`；`RunScreen.draw()` 大号字 | 每存好一张 +1 |
| 2 | 剩余张数 | `IntervalScheduler.getRemainingCount()` | 固定张数递减；无限模式显示“∞/无限” |
| 3 | 距下次拍摄倒计时（0.1 秒精度） | `IntervalScheduler.getCountdownMillis()` + `UiTheme.oneDecimal()`；UI 刷新 `TICK_MS=100` | 显示形如 `2.4s`，按 0.1 秒跳变 |
| 4 | 状态提示：待机/拍摄中/已暂停/已结束 | `IntervalScheduler.STATE_IDLE/RUNNING/PAUSED/FINISHED` + `stateName()`；另有 `STATE_ERROR` | 四种状态中文显示，颜色区分 |
| 5 | 确认键：开始 / 暂停 | `CaptureActivity.onKeyDown()` → `CameraKeyRouter.ACTION_ENTER` | 待机→开始；拍摄中→暂停；暂停→继续（**计数不重置**） |
| 6 | 下方向键：停止拍摄，回参数页 | `ACTION_DOWN` → `scheduler.stop()` → `showSettings()` | 停止后回到参数页，参数保留 |
| 7 | 上下键修改参数 | 参数页 `ACTION_UP/ACTION_DOWN` 移动焦点，`ACTION_LEFT/ACTION_RIGHT` 改值 | 上下移动 + 左右改值，与相机原生菜单习惯一致 |

## 四、逻辑规则

| # | 需求 | 实现 | 验收点 |
| --- | --- | --- | --- |
| 1 | 每次触发调拍照接口→存原图→**不编码视频** | `CaptureActivity.onTick()` → `scheduler.shouldTriggerNow()` → `CaptureService.takePicture()`；全工程无视频录制调用 | 任务结束 SD 卡里**只有照片**，没有任何视频文件 |
| 2 | 可随时暂停；继续不重置计数 | `IntervalScheduler.pause()/resume()`：`takenCount` 不变，`resume()` 重新起算下一张时间（`now + interval*1e6` ns） | 暂停/继续后张数连续累加 |
| 3 | 完成后提示“全部照片已保存至 SD 卡”，可选【是否生成延时视频】，**默认“否”** | `CaptureActivity.showFinishDialog()`；`DialogScreen.drawFinishDialog()` 中 `chooseVideo=false` 为默认焦点，绿框标在“否”上 | 直接按确认 = 不生成视频（安全默认） |
| 4 | 选“是”才做视频（可选附加功能） | `TimelapseJobWriter.writeJob()`：只在用户显式选“是”时写 `PMCACAP/TIMELAPSE_JOB.TXT`（张数/间隔/建议 24fps/成片时长/ffmpeg 示例命令） | 机内**不合成**视频、不动原图；只在电脑上后期合成 |
| 5 | 错误捕获：SD 卡满 / 读写失败 / 过热 → 立即停止 + 中文报错 | `HealthMonitor.checkBeforeShot()` / `onShotFailed()` / `checkTemperature()`；`IntervalScheduler.fail()`；`CaptureActivity.showErrorDialog()`；`DialogScreen.drawErrorDialog()` | 三类错误均有中文弹窗，弹窗后回到参数页，不继续拍摄 |
| 6 | 错误要“立刻停止” | `fail(reason)` 立即 `state=STATE_ERROR`、取消待触发、`captureService.cancelCapture()` | 无“补拍重试”逻辑，宁可停也不丢数据 |

## 六、与需求原文的**有意差异**（请知悉）

以下不是漏做，而是基于 A6000 实际操作习惯做的取舍，均已在界面/文档中体现：

1. **上下键的语义**：需求原文写“上下键：修改各项参数”，同时又要求“上下方向键：停止拍摄”。
   在只有 6 个物理按键的相机上，“上下移动焦点、左右改数值”才是相机原生菜单的一致体验，
   因此实现为：参数页 **上下=移动选项、左右=改数值**；运行页 **下=停止、上=开/关预览**。
   如果你更喜欢“上下一格一格改值”，改 `CaptureActivity.onKeyDown()` 里 `MODE_SETTINGS` 分支即可（两行）。
2. **存储格式的落地方式**：PMCA SDK 的静态拍照接口**不提供**“本次保存为 JPG 还是 RAW”的参数，
   实际文件格式由相机的机内菜单（影像质量/文件格式）决定。因此应用的做法是：
   参数页选择格式 + 醒目提示“请把相机机内格式设为对应项”，并在启动前做一次一致性提醒；
   拍摄动作本身统一走固件原生写卡，保证照片优先级最高、不引入应用侧编码风险。
3. **延时视频不在机内合成**：A6000 的 PMCA 运行时不具备可用的视频编码器/高性能 CPU，
   机内合成会带来过热、失败、丢照片的风险，与“照片第一优先级”冲突。
   因此“是”只写后期任务清单，视频在电脑上一条 `ffmpeg` 命令完成。
4. **温度不做回调注册**：`Temperature$StatusCallback` 的抽象方法名在不同固件版本不一致，
   注册会 `AbstractMethodError` 崩溃，故采用每 5 张轮询 `getStatus()` 的方式（更稳，代价是延迟几秒）。
