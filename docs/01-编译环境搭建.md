# 01 · 编译环境搭建

本文给出**两条**可用的编译路线：

- **路线 A（官方推荐）**：Android Studio / Gradle + 索尼官方 Camera Apps SDK —— 需要向索尼申请 SDK；
- **路线 B（本仓库已验证，无需 Gradle）**：JDK + Android build-tools 命令行流水线，用仓库自带的
  Sony 私有 API 编译期桩直接产出 APK。`tools\build-apk.ps1` 走的就是这条路线。

两条路线产出的 APK 在相机上等价，**签名证书都是 debug/release 均可**（相机接受自签名证书）。

---

## 0. 先明确几个“不是”的问题

| 常见误解 | 事实 |
| --- | --- |
| “用 Android Studio 正常建个手机 App 工程就行” | 不行。相机是 **Android 2.3.7（API Level 10）**，必须 `compileSdkVersion 10 / minSdkVersion 10`，且语言级别不能超过 Java 1.7（不要用 lambda、Stream、`try-with-resources` 之外的语法糖）。 |
| “把 SDK jar 打进 APK 一起安装” | 绝对不行。`com.sony.scalar.*` 的实现由相机固件提供，打进 APK 会造成重复类 / 启动崩溃，必须用 `compileOnly`（Gradle）或只参与 `javac -cp`（路线 B）。 |
| “用 OpenMemories-Framework 最省事” | 该框架依赖 jcenter（2021 年已停服），新环境基本拉不下来。本工程**不使用**该框架，直接按索尼私有 API 的签名手写调用。 |
| “需要 AndroidX / appcompat” | 不需要。API 10 上这些库既装不下也用不了，界面全部用 `Canvas` 自绘。 |

## 1. 通用前置

| 组件 | 版本要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 10/11 64 位 | 本文命令以 PowerShell 给出；macOS/Linux 把路径换成对应写法即可 |
| JDK | **8 / 11 / 17 / 21 任一**（路线 B 亦可用 JDK 25 + `-source 8 -target 8`） | 需 `javac`、`java`、`keytool` 在 PATH |
| Android SDK Build-Tools | **30.0.3**（28.x~34.x 均可） | 需 `aapt`、`zipalign`、`apksigner`；`d8` 在 30+ 才有 |
| Android SDK Platform | API 10（android-10）或任一 `android.jar` 作编译对照 | 路线 A 必需 |
| Gradle | 6.7.1（仓库已附 wrapper 配置） | 仅路线 A 需要；Gradle 8 对 `compileSdkVersion 10` 支持很差，别升太新 |
| Python | 3.8+ | 仅 PMCA-RE 需要（用官方 Windows 二进制时不需要） |

> 磁盘空间：Android SDK Build-Tools 约 300 MB，JDK 约 300 MB。不需要模拟器，不需要 NDK。

## 2. 路线 A：Gradle + 官方 Camera Apps SDK

### 2.1 安装 JDK 8（或 11）

1. 下载 Adoptium Temurin 8 或 11（x64）。
2. 安装时勾选 “Set JAVA_HOME variable”。
3. 验证：

```powershell
java -version
javac -version
echo $env:JAVA_HOME
```

> Gradle 6.7.1 与 JDK 8~11 最稳；JDK 17+ 需要 Gradle 7.3+，而 Gradle 7+ 对 API 10 工程支持变差，
> 所以**路线 A 建议就用 JDK 8/11**。

### 2.2 安装 Android SDK

1. 安装 Android Studio（可选）或仅 Android commandline-tools。
2. 用 `sdkmanager` 安装需要的组件：

```powershell
sdkmanager "platforms;android-10" "build-tools;30.0.3" "platform-tools"
```

3. 配置环境变量：

```powershell
[Environment]::SetEnvironmentVariable("ANDROID_HOME", "$env:LOCALAPPDATA\Android\Sdk", "User")
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
$env:Path += ";$env:ANDROID_HOME\platform-tools;$env:ANDROID_HOME\build-tools\30.0.3"
```

4. 验证：

```powershell
aapt version
zipalign -h
apksigner --version
```

### 2.3 获取索尼 PMCA SDK

索尼官方 Camera Apps SDK 不公开下载，需要走 PlayMemories Camera Apps 开发者计划申请
（历史上通过 `developer.sony.com` 的 Camera Apps SDK 页面提交申请，审核后提供 zip）。
拿到之后一般是 `CameraAppsSDK.jar` 或一组 jar + 文档 + 示例工程。

**工程内的接入方式**：把官方 jar 复制到 `app/libs/`，`app/build.gradle` 里已经写好：

```gradle
compileOnly fileTree(dir: 'libs', include: ['*.jar'])
```

`compileOnly` 的关键作用是：**参与编译，不写入 APK**。

> 没有官方 SDK 也能编译 —— 本仓库 `app/libs/sony-pmca-stubs.jar` 是按开源逆向工程资料
> （OpenMemories 项目的 jasmin 签名桩）重建的**编译期桩**，只保证类名/方法签名与固件一致，
> 不包含任何实现代码。用它编译出来的 APK 在相机上调用的是固件里的真实实现。
> 桩的局限：只覆盖本工程用到的 `CameraEx`、`Temperature`、`ScalarInput`、`Caution`、`KeyStatus` 等类。

### 2.4 生成 Gradle Wrapper

仓库只附带了 `gradle/wrapper/gradle-wrapper.properties`（指向 6.7.1）和 jar，
根目录的 `gradlew`/`gradlew.bat` 需要生成一次：

```powershell
# 本机已装 gradle 6.7.1 时
gradle wrapper --gradle-version 6.7.1

# 或者直接用已安装的 gradle 构建，不用 wrapper
gradle :app:assembleRelease
```

### 2.5 构建

```powershell
cd D:\sony\PMCA_IntervalCapture
gradle :app:assembleRelease
# 产物：app\build\outputs\apk\release\app-release-unsigned.apk
```

**注意**：Gradle 产物默认是 *unsigned*，必须签名后才能装进相机（见文档 02）。也可以直接在
`app/build.gradle` 里加 `signingConfigs` 使用 `build-support\pmca-debug.keystore`。

## 3. 路线 B：命令行流水线（本仓库已验证，推荐用于快速验证）

这条路不需要 Gradle、不需要联网、不需要官方 SDK，只用 JDK + Android build-tools。

### 3.1 目录约定

```
D:\sony\
├── build-support\
│   ├── libs\
│   │   ├── android-4.1.1.4.jar      # Android 编译期类库
│   │   ├── sony-pmca-stubs.jar      # 索尼私有 API 编译期桩
│   │   └── sony-stubs-src\          # 桩的 jasmin 源 + 生成器（可选，维护用）
│   ├── android-tools\android-15\    # aapt / aapt2 / d8.bat / apksigner.bat / zipalign
│   └── tmp\
└── PMCA_IntervalCapture\
    ├── app\libs\                    # 上面两个 jar 的副本（Gradle 路线用）
    ├── build-support\pmca-debug.keystore
    └── tools\build-apk.ps1
```

> `build-support` 是**本机自测工具链**，不属于应用源码。换机器时按 3.2 重新准备，
> 或直接把 `app/build.gradle` 的依赖指向你本机的 Android SDK。

### 3.2 准备步骤

1. **JDK**：装 JDK 8+，确保 `javac` 可用。

2. **Android build-tools**：装 SDK 后复制（或直接使用 SDK 内的）`aapt.exe`、`zipalign.exe`、
   `apksigner.bat`、`lib\apksigner.jar`、`d8.bat`、`lib\d8.jar`、`lib\dx.jar` 到
   `D:\sony\build-support\android-tools\android-15\`。

3. **Android 类库**：从 Android SDK 取 `platforms\android-XX\android.jar`，
   重命名为 `android-4.1.1.4.jar` 放到 `build-support\libs\`。

4. **索尼私有 API 桩**：使用本仓库 `app\libs\sony-pmca-stubs.jar`；如需重新生成：

```powershell
node D:\sony\build-support\libs\build-stubs.js
```

   该脚本会把 `sony-stubs-src\*.j`（jasmin 汇编格式的类签名）转换成 Java 源码 → `javac` 编译 →
   `jar` 打包。生成过程中不要写中文注释，否则会因编码不一致导致编译乱码。

5. **签名密钥**：仓库已带 `build-support\pmca-debug.keystore`（口令 `pmca123456`，别名 `pmca`）。
   想用自己的，重新生成：

```powershell
keytool -genkeypair -v `
  -keystore build-support\pmca-debug.keystore `
  -alias pmca -keyalg RSA -keysize 2048 -validity 10000 `
  -storepass pmca123456 -keypass pmca123456 `
  -dname "CN=PMCA IntervalCapture, OU=DIY, O=DIY, L=NA, ST=NA, C=CN"
```

> 相机的 app installer 接受 debug/release 自签名证书，不需要索尼官方签名。
> 但**同一个包名重新安装时签名必须一致**，否则要先卸载旧版本。

### 3.3 一键构建

```powershell
cd D:\sony\PMCA_IntervalCapture
powershell -ExecutionPolicy Bypass -File tools\build-apk.ps1
```

成功时最后几行应类似：

```
Verifies

package: name='com.pmca.intervalcapture' versionCode='2' versionName='1.0.1'
application-label:'间隔拍照'
构建完成：...\build\outputs\PMCA_IntervalCapture.apk
APK 大小：35.1 KB
```

## 4. 常见编译错误对照表

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `package com.sony.scalar.hardware does not exist` | 没把 `sony-pmca-stubs.jar` 放进 `app/libs/` 或没加到类路径 | 检查 `app/build.gradle` 的 `compileOnly fileTree(dir:'libs')`，或脚本里的 `-cp` |
| `cannot find symbol: method getAvailableBlocksLong()` | 用了 API 18+ 才有的 `StatFs` 方法 | 改用 API 10 的 `getBlockSize()*getAvailableBlocks()`（本工程已如此） |
| `cannot find symbol: class LambdaMetafactory` / `default method` | 语言级别用到了 1.8+ | 编译参数改 `-source 8 -target 8`，避免 lambda/默认方法 |
| `error: invalid source release: 1.6 / 1.7` | 新版 JDK 已删除 6/7 目标 | 用 `-source 8 -target 8` 即可（`minSdkVersion 10` 的 DEX 兼容） |
| `aapt: error: attribute android:versionCode not found` | 清单里漏了版本号，或 `-I android.jar` 缺失 | 清单里显式写 `android:versionCode` / `android:versionName` |
| `attribute value reference does not exist: @android:drawable/...` | 引用了框架内置资源，aapt 没带 `-I` 无法解析 | 用工程自有资源 `@drawable/ic_launcher`（本工程已改为自有 PNG） |
| `apksigner: Missing android.jar` / `No such file: lib/apksigner.jar` | build-tools 目录被裁掉了 lib 子目录 | 完整复制 build-tools 的 `lib\` 目录 |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE`（相机端） | 同包名但签名不同 | 先用 PMCA-RE 卸载旧版，再装新版 |
| `Unsupported class file major version 69` | d8 版本太老，读不了 JDK 25 的 class | 本工程用 `-source 8 -target 8` 输出 class 52，已规避 |
| `Picked up JAVA_TOOL_OPTIONS: ...` 刷屏 | 环境变量 `JAVA_TOOL_OPTIONS` 被设置 | `$env:JAVA_TOOL_OPTIONS=''` 后重新执行 |

## 5. 编码与换行约定

- 所有 `.java` / `.xml` / `.md` 一律 **UTF-8（无 BOM）**，源码里中文字符串很多，编码不一致会直接乱码。
- `javac` 必须带 `-encoding UTF-8`；Gradle 里加：

```gradle
tasks.withType(JavaCompile) {
    options.encoding = "UTF-8"
}
```

- 换行 LF/CRLF 都行，但 `.ps1` 建议 CRLF（部分 PowerShell 5.1 对 LF 脚本兼容一般）。
- **`.ps1` 脚本含中文时必须是 UTF-8 *带 BOM*（`EF BB BF`）**：Windows PowerShell 5.1 在没有 BOM 时会按
  系统 ANSI 代码页（中文系统 = GBK）解析脚本，中文注释变乱码，甚至“吃掉”引号/括号，报出
  `Unexpected token '}'`、`The hash literal was incomplete` 这类诡异语法错误（本工程踩过两次）。
  仓库内 `tools\*.ps1` 均已带 BOM；若改动后出现这类错误，重新加 BOM：

```powershell
$p = 'tools\build-apk.ps1'
$txt = [IO.File]::ReadAllText($p, [Text.Encoding]::UTF8)
[IO.File]::WriteAllText($p, $txt, (New-Object System.Text.UTF8Encoding($true)))
```

## 6. 验证清单（编译完成后必须确认）

```powershell
# 1. 签名是否有效（相机只认 v1 / JAR 签名；本工程显式关闭 v2/v3/v4）
apksigner verify --verbose --print-certs build\outputs\PMCA_IntervalCapture.apk

# 2. 包名、版本、最低 SDK、图标
aapt dump badging build\outputs\PMCA_IntervalCapture.apk

# 3. 确认私有类没有被误打进 APK（看“类定义”，不是在 dex 里搜字符串）
& "D:\sony\build-support\android-tools\android-15\dexdump.exe" -f build\work\dex\classes.dex |
  Select-String "Class descriptor" | ForEach-Object { $_.Line.Trim() } | Sort-Object -Unique
```

预期结果：

- `Verified using v1 scheme (JAR signing): true`（v2/v3/v3.1/v4 均为 false）
- `package: name='com.pmca.intervalcapture' versionCode='2' versionName='1.0.1'`
- `sdkVersion:'10'`、`application-label:'间隔拍照'`
- **`Class descriptor` 里只能出现 `Lcom/pmca/intervalcapture/...;`**。
  dex 中**会**出现 `Lcom/sony/scalar/hardware/CameraEx;` 这类**类型引用**（方法签名的一部分），这是正常的；
  一旦出现 `Class descriptor: 'Lcom/sony/...;'` 才说明私有桩被误打包，上机必崩。
